# RFP Insight — 프로젝트 요구사항 v1.0

## 1. 프로젝트 개요

**프로젝트 목적:** 제안요청서(RFP)를 분석하고, 핵심 정보를 구조화하여 문서 검토 시간을 줄이는 AI 웹 애플리케이션 개발.

**대상 사용자:** 공공기관 입찰에 참여하는 기업의 실무자, 제안서 작성 담당자, 입찰 컨설턴트.

**해결할 문제:** 긴 제안요청서에서 예산, 일정, 필수 요구사항 등을 확인하는 데 시간이 소요되며, 문서 검토 과정에서 중요한 조건이 누락될 수 있음.

## 2. 핵심 기능 (구현된 MVP)

- F01: PDF 업로드, 페이지별 텍스트 확인 및 개별 페이지 분석
- F02: 사업명, 사업기간, 사업비, 사업목적, 제출기한 추출
- F03: Groq API를 통한 값·인용문·PDF 페이지 번호의 JSON 구조화
- F04: 3페이지 단위 순차 분석, 진행률 및 그룹별 결과 표시
- F05: 후보 병합, 사업명 교차 확인 및 사업기간 정규화를 통한 대표값 선택
- F06: 사업비 금액 및 일부 조건 검증, 인용문·페이지 대조와 실패 상세 표시
- F07: 세션 내 결과 유지, 문서 변경·업로드 해제 시 초기화
- F08: 기본 디스크 저장·복원 비활성화, 명시적 로컬 설정에서만 캐시 활성화

## 3. 예외 처리

- 파일 형식이 잘못된 경우 오류 안내
- 텍스트 추출이 불가능한 스캔 PDF는 지원하지 않음을 안내
- 문서에서 확인되지 않는 항목은 임의로 생성하지 않음
- API 요청 실패 및 사용량 제한 발생 시 사용자에게 상태 안내

## 4. 기술 구성

- 언어: Python
- PDF 처리: pypdf
- LLM API: Groq
- 웹 UI: Streamlit
- 형상 관리: Git / GitHub
- 설정: python-dotenv, 환경변수 / 테스트: unittest
- 배포: Streamlit Cloud 배포 경험 (현재 운영 상태 미확인)

## 5. 품질 평가

여러 RFP 문서를 대상으로 주요 항목 추출의 정확성, 누락 여부, 근거 페이지의 정확성, 응답 시간을 측정한다.

금액, VAT 포함 여부, 기간 및 예산 조건은 각각 검증한다.

## 6. MVP 제외 범위

- 사용자 회원가입 및 로그인
- 여러 사용자의 동시 문서 관리
- HWP 및 스캔 PDF OCR 처리
- 자체 LLM 사전학습 또는 미세조정
- 자동 입찰 제안서 작성

## 7. MVP 완료 기준

텍스트 기반 PDF 한 개에서 5개 항목을 추출하고 후보를 병합하여 대표값과 판단 상태를 표시한다. 근거가 부족하거나 대표값을 확정하지 못하면 검토 필요로 남긴다. 원문 인용·페이지 검증 실패를 성공으로 표시하지 않는다.

분석 진행과 결과는 현재 세션에서 유지하며 공개 배포 기본값에서 디스크 캐시를 읽거나 쓰지 않는다. 문서 변경 시 이전 분석 상태를 초기화한다. 문서 텍스트의 Groq 전송을 화면에 안내한다.

기존 테스트 및 캐시·세션 정책 회귀 테스트를 API 호출 없이 통과하고, 실제 배포 동작은 별도 수동 점검한다. 기존 평가 PDF·캐시·베이스라인·정답은 보존한다.

기존에 목표로 둔 서로 다른 RFP 최소 3개 시험은 추가 평가 목표로 남긴다. 현재 기록된 LMS와 K-sure 평가만으로 일반화 정확도나 상용 품질을 주장하지 않는다. LMS는 알고리즘 개발에도 사용한 문서이며 상세 수치는 README를 따른다.

## 8. 향후 확장 (미구현, MVP 완료 조건에서 제외)

- RAG 질의응답: 문서 구간 검색, 임베딩·벡터 검색 및 검색 근거 기반 답변
- 다양한 레이아웃·장문 사업목적 처리와 독립 문서 평가 확대
- 사용자별 영구 문서 관리, 인증 및 운영 정책
