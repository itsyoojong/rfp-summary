# MVP v1.0 결과 화면 개선

작업일: 2026-11-20. 시작 상태는 `main`, 미커밋 변경 없음.

## 변경 파일

- `app.py`: 기존 분석·세션·진행률·오류 처리 흐름을 유지하고 결과 표시를 UI 함수에 연결했다. 사업비 금액/조건 및 원문 검증은 카드 표시 전에 기존 함수로 실행한다. 개별 페이지 JSON도 펼침으로 이동했다.
- `src/result_ui.py`: 전달받은 결과를 수정하지 않는 카드·검증·상세 화면 함수를 분리했다. 기존 app.py의 결과 출력 영역이 길어져 UI 부분만 별도 모듈로 옮겼다.
- `tests/test_result_ui.py`: 실제 병합·선택·검증 함수와 Mock 데이터로 표시 상태 및 AppTest 검증을 추가했다.
- `docs/ui_completion.md`: 구현·검증 범위와 배포 점검 항목을 기록했다.

## 구성

1. 사업명 전체 폭 강조 카드
2. 사업기간·사업비 두 열 카드 (좁은 화면에서는 세로 배치)
3. 사업목적 및 제출기한 전체 폭 카드
4. 검증 결과: 인용 일치 수, 검토 필요·미확인 항목, 사업비 경고
5. 상세 데이터: 원문 인용문, 검증 실패·지정 페이지 원문, 최종 JSON, 전체 후보, 대표값 선택 상세 JSON, 그룹별 JSON

긴 사업목적은 320자 앞부분을 먼저 표시하고 전체 펼침을 제공한다. `◯`, `○`, `●` 구분 기호 앞에는 표시용 문단 경계만 추가한다. 요약·재작성·추가 LLM 호출은 없다. 대표값이 없으면 미확정 후보로 표시하며 확정 정보가 아니라고 안내한다.

그룹 진행 중에는 중간 결과임을 표시하고, 기존 재실행에서 최신 선택값으로 다시 렌더링한다.

## 검증 상태 기준

- **미확인**: 병합된 후보가 없음. 제출기한을 추정하거나 채우지 않는다.
- **근거 확인**: 대표값 존재, 해당 선택 후보의 `valid_pages` 존재, 인용 실패 없음, 해당 필드의 `validate_sources()` 실패 없음. 사업비는 기존 금액·조건 검증 경고도 없어야 한다.
- **검토 필요**: 후보는 있지만 위 조건을 충족하지 않음. 인용 일부가 실패하거나 기간 충돌로 대표값이 없을 때도 유지한다.
- **복수 후보 통합 완료**: 후보 여러 개 중 기존 resolver가 대표값을 선택했음을 별도 표시한다. 근거 확인과 독립적이며 인용 실패가 있으면 검토 필요와 함께 표시한다.

보수적으로, 선택되지 않은 후보의 인용 실패도 해당 항목의 검토 필요 상태에 반영한다. 카드의 선택 판단에는 기존 resolver 상태도 별도로 남긴다. 인용 일치는 추출값의 의미나 모든 VAT·상한 조건의 정확성을 보장하지 않는다고 안내한다.

기존 JSON의 항목별 status·selected 구조, 원본 후보 JSON, 원문 검증 실패 JSON 및 그룹 JSON은 펼침에서 유지한다. 화면용 신뢰 상태는 기존 알고리즘의 판단을 덮어쓰지 않는다.

## 실제 브라우저 확인과 미검증 범위

가상 데이터만 사용하는 별도 임시 미리보기에서 실제 브라우저 확인을 수행했다. 데스크톱 기본 폭과 390×844 좁은 화면에서 사업기간·사업비 카드의 배치/줄바꿈, 미확정 사업목적의 앞부분·전체 펼침, JSON 펼침 접근을 확인했다. 화면 폭 설정은 확인 후 원복했다. 실제 사용자 PDF나 API를 사용하지 않았다.

Cloud 배포 화면은 미검증이다. 배포 후 실제 PDF로 그룹 진행 중/완료 카드 갱신, 다른 문서로 바꿀 때 초기화, 긴 문장·영문/URL 등 긴 단어 줄바꿈, 시크릿 세션 분리, 원문 실패 상세·JSON 펼침을 확인해야 한다. 스마트폰 실기기는 확인하지 않았다.

기존 한계인 인용 페이지 불일치, 장문 목적 추출 품질, 제한적인 평가 범위와 부분적인 사업비 조건 검증은 그대로 남아 있다. 이번 변경은 출력 방식 개선이며 분석 알고리즘이나 정확도를 개선한 것으로 주장하지 않는다.

새 라이브러리, 프레임워크, AI 기능은 추가하지 않았다. 분석 프롬프트·모델·검증/후보 선택 알고리즘·평가 데이터는 변경하지 않았다. 커밋·Push·배포는 수행하지 않았다.
